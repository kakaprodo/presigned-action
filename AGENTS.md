# Presigned Action package guidance

## Temporary access keys

- `TemporaryAccessKey` records are generated by `GenerateTemporaryAccessKeyAction`.
- Store the deterministic `$data->dataKey()` value in `reference_text` whenever a key is created or refreshed.
- Reuse an existing key only when `is_independent`, `accessible_id`, `expires_at > now()`, and `reference_text` match. Do not use `whoami`, scopes, permissions, origin, or accessible type as additional reuse clauses; those values are represented by the data key or are validated separately.
- Keep `reference_text` mass assignable on the model.

## Migrations

- Keep the first temporary-access-key migration as the canonical schema, including nullable `accessible_type`/`accessible_id` and the `is_independent` flag.
- Add later schema changes in separate timestamped migrations. Make additive migrations idempotent by checking `Schema::hasColumn()` before adding columns and before dropping them in `down()`.
- Keep the independent-key migration safe to run against schemas that may already contain some of its columns.

## Verification

- Run `composer test` after changes.
- When changing key reuse behavior, cover both reuse for identical data and creation of a new key when the generated data key changes.

## Release notes

- Always add or update a versioned release note under `/doc` for every package change.
- Follow the existing `doc/<version>-release.md` format and summarize the user-visible changes under a highlights section.
