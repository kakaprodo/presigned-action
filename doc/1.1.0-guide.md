# Presigned Action 1.1.0 Guide

This guide covers the features and behavior introduced in version 1.1.0.

## 1. Access-key generation changes

When an access key is generated, the package searches for a non-expired key
matching the accessible model, `whoami`, `origin`, scopes, and permissions.
The query explicitly requires:

```php
->where('expires_at', '>', now())
```

An unexpired matching key is returned. Expired keys are not renewed or reused;
the package creates a new key instead. The old key remains available until it
is removed by the purge command.

The old `GenerateTemporaryAccessKeyData::accessKeyIsGeneratedWithSameValues()`
method is no longer available. Applications should not call it.

## 2. Purging expired keys

Run the new Artisan command manually or schedule it in the application:

```bash
php artisan presigned-action:purge-expired
```

The command deletes records whose `expires_at` value is less than or equal to
the current time.

Example scheduler registration:

```php
$schedule->command('presigned-action:purge-expired')->daily();
```

## 3. Permission shortcut

`TemporaryAccessKey::can()` is an alias for `hasPermission()`:

```php
if ($accessKey->can(['orders.view'])) {
    // The key grants at least one requested permission.
}
```

Like `hasPermission()`, it returns `true` when at least one requested
permission is present on the key.

## 4. Origin middleware

`PresignedActionOriginMiddleware` verifies that the current temporary access
key has the origin declared by the route. The middleware accepts comma- or
pipe-separated values and allows the request when one requested origin
matches.

Register the alias in the application's HTTP kernel:

```php
protected $middlewareAliases = [
    'presigned-action.origin' =>
        \Kakaprodo\PresignedAction\Middleware\PresignedActionOriginMiddleware::class,
];
```

Use it after the access-key verification middleware:

```php
Route::middleware([
    VerifyAccessKeyMiddleware::class,
    'presigned-action.origin:partner-api',
])->get('/orders', ...);
```

The package does not register this alias automatically.
The existing scope middleware alias must also be registered by the application
if the alias form is used:

```php
'presigned-action.scope' =>
    \Kakaprodo\PresignedAction\Middleware\PresignedActionScopeMiddleware::class,
```

## 5. Permission middleware

`PresignedActionPermissionMiddleware` checks permissions on the current access
key. Register and use it in the same way:

```php
protected $middlewareAliases = [
    'presigned-action.permission' =>
        \Kakaprodo\PresignedAction\Middleware\PresignedActionPermissionMiddleware::class,
];
```

```php
Route::middleware([
    VerifyAccessKeyMiddleware::class,
    'presigned-action.permission:orders.view,orders.update',
])->get('/orders', ...);
```

Permission values may also be separated with `|`. The middleware allows the
request when at least one requested permission is granted.

## 6. Custom action validators

Validators are registered and consumed through the facade. The current
temporary access key is injected as the first callback argument.

### Grouped validators

```php
use Kakaprodo\PresignedAction\Facades\PresignedAction;
use Kakaprodo\PresignedAction\Models\TemporaryAccessKey;

PresignedAction::validator()->register('orders', [
    'owns' => fn (TemporaryAccessKey $accessKey, int $orderId) =>
        $accessKey->whoami === (string) $orderId,
]);

PresignedAction::validator()->check('orders.owns', [$orderId]);
```

### Standalone validators

```php
PresignedAction::validator()->register(
    'has-access',
    fn (TemporaryAccessKey $accessKey, string $resource) => $accessKey->can([$resource]),
);

PresignedAction::validator()->check('has-access', ['orders.view']);
```

### Nested validator paths

Validator names use Laravel's dot notation and are resolved with `Arr::get()`:

```php
PresignedAction::validator()->register('resources', [
    'orders' => [
        'can-update' => fn (TemporaryAccessKey $accessKey) =>
            $accessKey->can(['orders.update']),
    ],
]);

PresignedAction::validator()->check('resources.orders.can-update');
```

If the validator path does not resolve to a handler, `check()` throws:

```text
Validator [resources.orders.missing] is not defined.
```

### Validation failures and custom messages

If a validator returns a falsy value, `check()` throws a
`PresignedActionException` with the default message `Permission denied`:

```php
PresignedAction::validator()->check('orders.owns', [$orderId]);
```

Pass a third argument to customize the message:

```php
PresignedAction::validator()->check(
    'orders.owns',
    [$orderId],
    'You cannot access this order.',
);
```

## 7. Migration notes

Version 1.1.0 removes the data comparison helper and changes expired-key
behavior. Update applications that called
`accessKeyIsGeneratedWithSameValues()` or expected expired keys to be renewed
in place.
