# Release 1.2.0

## Highlights

- Add short-lived, single-use temporary authentication codes for QR-code login flows cases.
- Add a configurable unauthenticated generation route with a default limit of 20 requests per minute.
- Add gate methods for generating, associating, and consuming temporary authentication codes.
- Store application-specific subscriber information in JSON `metadata` without coupling the package to a specific application or POS system.
- Purge expired, unused authentication codes with the existing `presigned-action:purge-expired` command.

## Temporary authentication-code lifecycle

Temporary authentication codes are intended for a short-lived handoff between
two applications. For example, one application can display a QR code while a
second application scans it and supplies subscriber information.

The lifecycle is:

1. The requesting application creates a unique `state_key`.
2. It calls the public generation route with that state key.
3. The package creates a UUID and stores a code that expires after 20 seconds.
4. Only the UUID is placed in the QR code.
5. The scanning application associates a subscriber and metadata with the UUID.
6. The requesting application polls with the original `state_key` and UUID.
7. The first successful completed fetch returns the subscriber data and deletes the code.

The `state_key` is generated by the client and must be unpredictable and
unique for every authentication request. The package validates that it is a
required string, limits it to 500 characters. The package cannot determine whether
a client-generated value has enough entropy, so clients should use a cryptographically random value.

## Configuration

The feature is configured under `presigned-action.temp_auth_code`:

```php
'temp_auth_code' => [
    'table' => 'temp_auth_codes',
    'expires_after' => 20,
    'route' => [
        'enabled' => true,
        'prefix' => 'api/presigned-action',
        'generate_uri' => 'temp-auth-codes',
        'middleware' => [],
    ],
    'rate_limit' => [
        'enabled' => true,
        'max_attempts' => 20,
        'window_seconds' => 60,
        'key_resolver' => null,
    ],
],
```

With the default route configuration, the endpoint is:

```text
POST /api/presigned-action/temp-auth-codes
```

The route is unauthenticated by default. It is protected by a rate limiter
that allows 20 generation requests per 60-second window per requester IP.
`key_resolver` can be set to a callable when the application needs to rate
limit by device, tenant, application ID, or another identifier. Additional
route middleware can be supplied through `route.middleware`.

Set `route.enabled` to `false` when the application wants to call the gate
directly or expose its own controller route.

## Migration and table name

When `should_run_migration` is enabled, the package loads the migration that
creates the configured temporary-auth-code table. The default table is
`temp_auth_codes`.

The table contains:

| Column            | Purpose                                                         |
| ----------------- | --------------------------------------------------------------- |
| `uuid`            | Public, randomly generated code identifier and QR-code content. |
| `state_key`       | Client-generated correlation key. It is unique.                 |
| `subscriber_id`   | Optional subscriber identifier.                                 |
| `subscriber_type` | Subscriber mode/type supplied by the application.               |
| `metadata`        | Optional JSON data returned to the requesting application.      |
| `expires_at`      | Absolute expiration timestamp.                                  |

To use another table name, configure it before running migrations:

```php
'temp_auth_code' => [
    'table' => 'custom_temp_auth_codes',
],
```

The `TempAuthCode` model reads the same configuration, so generation, lookup,
association, fetching, and cleanup all use the configured table.

## Generate a temporary authentication code

The public route accepts JSON containing a required string `state_key`:

```http
POST /api/presigned-action/temp-auth-codes
Content-Type: application/json

{"state_key":"unique-login-request-state"}
```

The response is:

```json
{
    "uuid": "9b1deb4d-3b7d-4bad-9bdd-2b0d7b3dcb6d",
    "state_key": "unique-login-request-state",
    "expires_at": 1789009228
}
```

The UUID is the complete QR-code content. Do not put the state key in the QR
code unless the application deliberately needs to do so for its own protocol.
The requesting application must retain the state key for the later fetch.

The same operation is available through the presigned action gate:

```php
use Kakaprodo\PresignedAction\Facades\PresignedAction;

$code = PresignedAction::generateTempAuthCode([
    'state_key' => $stateKey,
]);
```

Generation fails when the state key is missing, is not a string, exceeds 500
characters, or has already been used. A new authentication request should use
a new state key and will always receive a new UUID.

## Associate subscriber information

The package does not expose a subscriber-association route. The application
that has authenticated or validated the scanner calls the gate directly:

```php
PresignedAction::associateTempAuthCode([
    'uuid' => $code->uuid,
    'subscriber_id' => 'subscriber-42',
    'subscriber_type' => 'subscriber',
    'metadata' => [
        'access_token' => $token,
        'display_name' => 'Example User',
    ],
]);
```

`subscriber_id` is optional. `subscriber_type` identifies the application’s
subscriber mode or type. `metadata` is application-defined JSON and is returned
to the requesting application after successful consumption.

Association fails when the UUID does not exist or the code has expired. The
application is responsible for validating the subscriber before calling this
method.

## Consume a temporary authentication code

The requesting application polls through the gate using both values:

```php
$result = PresignedAction::fetchTempAuthCode(
    $stateKey,
    $code->uuid,
);
```

While the scanner has not associated a subscriber, the result is:

```php
[
    'status' => 'pending',
    'expires_at' => 1789009228,
]
```

After association, the result is:

```php
[
    'status' => 'completed',
    'subscriber_id' => 'subscriber-42',
    'subscriber_type' => 'subscriber',
    'metadata' => [
        'access_token' => '…',
    ],
]
```

Completed fetches are transactional and single-use. The code is deleted after
its completed result is prepared, so a second fetch cannot retrieve the same
subscriber information. A mismatched state key, unknown UUID, expired code,
or already-consumed code results in an error and should stop client polling.

## Purge expired, unused codes

Codes that expire before a subscriber is associated remain in the database
until cleanup runs. The existing command removes both expired temporary access
keys and expired temporary authentication codes:

```bash
php artisan presigned-action:purge-expired
```

The command is safe to run repeatedly. It deletes records whose `expires_at`
is less than or equal to the current time and uses the configured temporary
authentication-code table.
