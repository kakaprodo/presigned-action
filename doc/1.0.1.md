# Release notes: v1.0.1

This release improves temporary access-key identity, authorization metadata,
and key renewal behavior.

## Highlights

### Additional access-key attributes

Access keys now support:

- `origin`: an optional string identifying the source system or integration.
- `permissions`: an optional JSON array containing granted permissions.

Both attributes are mass-assignable on `TemporaryAccessKey`. The model casts
`permissions` to an array.

Example:

```php
$accessKey = PresignedAction::generateAccessKey([
    'accessible' => $order,
    'whoami' => 'partner-42',
    'origin' => 'partner-api',
    'scopes' => ['orders.read'],
    'permissions' => ['orders.view'],
]);
```

### Key reuse and renewal

Key lookup now considers the accessible model, `whoami`, and `origin`.
Scopes and permissions are compared as unordered values before a key is reused
or renewed.

- Matching, unexpired keys are returned unchanged.
- Matching, expired keys are renewed in place with a new UUID and expiration.
- Different scopes, permissions, or origin values create a new key.

This prevents a key generated for one set of capabilities from being reused for
a different set of capabilities.

### Model helpers

`TemporaryAccessKey` now provides:

```php
$accessKey->revalidateAccisible($accessible);
$accessKey->revalidateWhoami($whoami);
$accessKey->hasScope(['orders.read']);
$accessKey->hasPermission(['orders.view']);
```

`hasScope()` and `hasPermission()` return `true` when at least one requested
value is granted.

## Migration

The release adds the following nullable columns to `temporary_access_keys`:

```text
permissions JSON NULL
origin       VARCHAR NULL
```

Run the application migrations during deployment:

```bash
php artisan migrate
```

The package includes both the updated create-table migration and an upgrade
migration for installations that already have the table.
